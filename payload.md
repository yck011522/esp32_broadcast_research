# Robots-to-PC Payload Specification

The PC sends one shared **World State** at **50 Hz**. Each of the four cars (mini robots) sends its own **Robot State** at **20 Hz**. The PC sends high-level intent (joystick positions, track topology status); each car performs line following, motor control, NFC-based localization, and intersection execution locally.

At non-regular intervals, PC can send a **Configuration command** to change robot parameters (PID gains, max speed, etc.)

## Transport and Encoding

- Transport through Bluetooth LE that is available on ESP32S3.
- ESP32 on the **Robot** acts as **Server** side, advertise itself, provide one **Service** that contain multiple **Characteristics**.
- Each Characteristic is a fixed size **Binary Packet**.
- Each packet is a self-contained **latest snapshot**, old packets can be discarded at all layers.
- USB serial framing may add a newline, but that newline is not transmitted over ESP-NOW.

# World State

Sends out at approximately 50Hz
This will "Write without response" to the "world_state" characteristic of each car. All cars will receive the same World State packet.
If more a world state is pending to be sent to a car but a new world state is received from the computer, the new world state will be sent and the old one will be dropped. The car will always receive the latest world state.

| Name | Expected format | Bytes | Type | Meaning of that property |
| --- | --- | ---: | --- | --: |
| `msg_type` | `W` | 1 | char | Message type identifier for World State. |
| `world_seq` | `0-65535` | 2 | uint16 | Monotonically increasing World State sequence number, typically at 50Hz / 20ms interval. Used by each car to detect missing broadcasts. |
| `topology_id` | `0-255` | 1 | uint8 | ID of the active predefined map/topology configuration. Only a few configurations are possible. |
| `movement_command_1` | bit mask | 1 | bits | Movement Command for Car 1. |
| `movement_command_2` | bit mask | 1 | bits | Movement Command for Car 2. |
| `movement_command_3` | bit mask | 1 | bits | Movement Command for Car 3. |
| `movement_command_4` | bit mask | 1 | bits | Movement Command for Car 4. |


## Topology ID

Topology is related to whether some roads or intersections are passible or not due to changing road conditions. Bridge 1 to 4 are movable. At any time, some of the bridges can be missing or under operations. The exact configuration mapping of the `topology_id` is TBD after gameboard design.

The topology is generated by PC, sent and stored locally in every car. PC relies on the latest `world_seq` in received telemetry to confirm that the car received the latest topology before actually removing any bridges.

`topology_state` selects one of the predefined s. The car combines this topology information with its locally detected NFC marker to determine its navigation state without requiring an additional communication round trip to the PC.

## Movement Command Encoding

| Bit Position | Name | Meaning |
| --- | --- | --- |
| 0 | `forward` | `1` = FORWARD, `0` = STOP. |
| 1 | `turn_left` | `1` = Left turn at next intersection if possible |
| 2 | `turn_right` | `1` = Right turn at next intersection if possible (right turn presides if coexist with `turn_left`) |

Examples:

- `0` , `2`, `4` = stop
- `1` = forward and continue straight.
- `3` = forward and take the left branch.
- `5` = forward and take the right branch.

STOP takes precedence over the branch command.

Turn signals are indicators for the car controller to make line following decisions at the intersection decision point.

# Configuration Command

Sends out at sparse irregular times.
This packet will "Write with response" to the "config_command" characteristic of each car. Each connected car will respond with a "config_ack" packet and for the modem to retry if the ack is not received within a timeout.
The PC side will be able to read the latest telemetry from each car to confirm that the world_seq in the ack is equal to the world_seq in the config command. If not, the PC can retry sending the config command until it receives a valid ack.

| Name | Expected format | Bytes | Type | Meaning of that property |
| --- | --- | ---: | --- | --: |
| `msg_type` | `C` | 1 | char | Message type identifier for Configuration Command. |
| `world_seq` | `0-65535` | 2 | uint16 | Monotonically increasing World State sequence number, typically at 50Hz / 20ms interval. Used by each car to detect missing broadcasts. |

Other configuration parameters are TBD.

# Robot State

Each car sends one Robot State packet at approximately **20 Hz**.

| Name                      | Expected format                     | Bytes | Type   |                                     Meaning of that property |
| --- | --- | ---: | --- | --: |
| `robot_id` | `1-4` | 1 | uint8 | Identifies which car generated this telemetry packet. |
| `telemetry_seq` | `0-65535`                           | 2     | uint16 | Sequence number incremented for every Robot State transmission. <br />Allows the PC to detect missing telemetry packets. |
| `last_world_seq`          | `0-65535`                           | 2     | uint16 | Most recent valid World State sequence number received and applied by this car. <br />Zero before the first World State packet is received. |
| `world_packets_lost_5s` | `0-255` | 1 | uint8 | Number of missing World State sequence numbers detected during the most recently completed one-second measurement window. The reported value remains fixed until the next one-second window completes. |
| `nfc_marker_id` | `0-65535` | 6 | bytes | The 2nd to 7th byte of the NFC tag's UID. 1st byte skipped because they are the same. |
| `nfc_marker_age_ms` | `0-65535` | 2 | uint16 | Milliseconds elapsed since the most recent valid NFC marker detection. |
| `controller_follow_state` | `0-4` | 1 | uint | Current local intersection/navigation FSM state. |
| `left_speed_mm_s` | signed integer, `-32768` to `32767` |  | 6 | Current measured left-wheel speed in mm/s, derived from encoder feedback through the motor driver. Positive and negative signs indicate direction. |
| `right_speed_mm_s` | signed integer, `-32768` to `32767` |  | 6 | Current measured right-wheel speed in mm/s, derived from encoder feedback through the motor driver. Positive and negative signs indicate direction. |
| `battery_mv` | `0-65535` |  | 5 | Measured battery voltage in millivolts. Example: `12420` = 12.420 V. |

## Controller Follow State

| Code | State | Meaning |
| --- | --- | --- |
| `0` | `FOLLOW_LINE` | Normal line following outside an intersection. |
| `1` | `TURNING_LEFT` | Steep left turn happening |
| `2` | `TURNING_RIGHT` | Steep right turn happening |
| `3` | `APPROACHING_BRANCH` | On top of intersection marker, car is approaching its decision point. |
| `4` | `BRANCHING_CENTER` | Inside branch zone - keep line center |
| `5` | `BRANCHING_LEFT` | Inside branch zone - keep left edge |
| `6` | `BRANCHING_RIGHT`     | Inside branch zone - keep right edge                         |
| `7` | `MERGING_FROM_CENTER` | Inside merging zone - keep line center |
| `8` | `MERGING_FROM_LEFT` | Inside merging zone - keep left edge |
| `9` | `MERGING_FROM_RIGHT` | Inside merging zone - keep right edge |
| `10` | `LINE_LOST` | Line lost and car is unsafe to move |

# Wireless Quality Monitoring

Default monitoring window 5 seconds, fixed window or moving window depends on  implementation.

## PC to Car : World Packet Loss Count

Each car compares incoming `world_seq` values.

Example:

```text
100 -> 101 -> 104
```

indicates two missing packets: 102 and 103.

## PC to Car : World Silence Duration

The robot detects length of radio silence as received. Report maximum gap duration over the monitoring window.

## Car to PC : Telemetry Packet Loss Count

The PC detects missing Robot State packets by observing gaps in each car's `telemetry_seq`.

## Car to PC : Silence Duration

The robot detects length of radio silence as received from car
